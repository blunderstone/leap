## Overview

We will address the eight defects, design gaps, and documentation omissions identified in GitHub Issue #36. The implementation strategy follows an incremental approach: establishing project-wide linter correctness first, refactoring and automating the interactive installer scripts next, and completing the taxonomy/migration documentation last.

**Development Approach:** Use Test-Driven Development (TDD) throughout. We will write and update test assertions to cover all modified code paths in both Python and shell scripts before or alongside the implementation changes, verifying success at the end of each phase.

### Overall Assessment

- **Complexity:** MEDIUM - Requires refactoring POSIX-compatible shell arguments, string splitting in Python, and updating relative path structures while maintaining strict testing standards.
- **Risk:** LOW - All changes are auxiliary workspace tooling, configuration, and documentation. No production linter runtime engine code is impacted.

## Phase 1: Project-Wide Markdown Linting & Clean Templates

### Goals

- Establish a root-level `.check-md.yml` configuration with sensible exclusions.
- Update the unified check runner (`scripts/run-all-checks.sh`) to run linter checks repository-wide.
- Fix all pre-existing Markdown lint violations in repository files outside `kb/`.
- Ensure all template files written by `setup-leap.sh` are generated lint-clean.

### Approach

- **Config Creation:** Create `.check-md.yml` in the root directory. Exclude python virtual environments, caches, coverage files, and local agent/backup directories (`.venv`, `htmlcov`, `.gemini`, `.claude`, `.cursor`, `.aider`, `.windsurf`, `*.bak`).
- **Check-Runner Update:** Change `scripts/run-all-checks.sh` to call `check-md` (which automatically locates `.check-md.yml` from the root) on the whole repository rather than a hardcoded `kb/` path.
- **Linter Violations Repair:** Correct Rule 2 (blank line separation) and Rule 3 (heading increment) violations in `.github/ISSUE_TEMPLATE/bug-report.md`, `.github/ISSUE_TEMPLATE/leap-improvement-proposal.md`, `LICENSE.md`, and any active `dev-note-*.md` files.
- **Template Corrections:** Adjust the heredocs inside `scripts/setup-leap.sh` (specifically the `For example:` block inside `CLAUDE.md` template, and any other template issues) to include proper blank lines before list blocks.

### Testing

- Execute `./scripts/run-all-checks.sh` to ensure `check-md` successfully scans the entire workspace and reports 0 errors.

### Success Criteria

- [ ] `.check-md.yml` is created and configured.
- [ ] `scripts/run-all-checks.sh` lints the entire repository.
- [ ] All pre-existing workspace markdown violations outside `kb/` are fixed.

### Explicitly Deferred

**Rationale:** Establishing a repository-wide lint-clean state prevents pre-commit check failures and ensures that newly generated files do not break CI.

## Phase 2: Setup Script & Skill Installation Refactoring

### Goals

- Standardize all prompt defaults to "no" in `scripts/setup-leap.sh`.
- Implement non-interactive flag support and CLI help in `setup-leap.sh`.
- Enhance `install-skills.py` to support comma-separated agent selections.
- Track configured agents in `setup-leap.sh` and pass only those to `install-skills.py`.
- Apply root-anchored ignore patterns in `.gitignore`.
- Update setup closing instructions to recommend modern workspace skills (e.g. `leap-start`).

### Approach

- **Prompt Defaults:** Modify all interactive prompt questions in `setup-leap.sh` to default to `n`/`N`.
- **CLI Flag Parsing:**
  - Add robust argument parsing loop to `setup-leap.sh` to handle `-y`, `--yes`, `-n`, `--no`, `--help`, and component-specific overrides (e.g., `--claude`, `--gemini`, `--cursor`, `--skills`, `--gitignore`, `--hooks`, `--qmd`, `--submodule-recurse`, `--check-md`).
  - Introduce `NON_INTERACTIVE` and `DEFAULT_ANSWER` flags.
  - Refactor `ask_yes_no` and `ask_choice` to bypass interaction and use preset overrides or default choices when running non-interactively.
- **Comma-Separated Skills Support:**
  - Update `scripts/install-skills.py` to split the `target_agent` argument on commas: `targets = [t.strip() for t in target_agent.split(",") if t.strip()]`.
- **Precise Skill Deploy:**
  - Track configured agents in `setup-leap.sh` inside an `INSTALLED_AGENTS` variable (e.g., appending `claude`, `aider`, `gemini`, `cursor`, `windsurf` based on user selections).
  - Run `install-skills.py` passing only the comma-separated `INSTALLED_AGENTS` string instead of `all`.
- **Root-Anchoring Patterns:** Update `configure_gitignore` in `setup-leap.sh` to write root-anchored ignore directories (starting with `/` like `/.gemini/` instead of bare `.gemini/`), preventing accidental shadowing of nested files.
- **Closing Instruction Update:** Replace the legacy closing message with recommendations to invoke the modern `leap-start` skill.

### Testing

- Update existing shell test scripts or add dedicated integration tests verifying that `setup-leap.sh --yes` and `setup-leap.sh --no` run to completion without user input, configuring correct settings.
- Update Python unit tests in `scripts/tests/test_install_skills.py` to assert correct multi-agent targets (comma-separated lists) are parsed and installed.

### Success Criteria

- [ ] Interactive prompts in `setup-leap.sh` default to "no".
- [ ] Setup script accepts `--yes`, `--no`, and component-specific arguments.
- [ ] `setup-leap.sh` executes fully non-interactively when flags are provided.
- [ ] `install-skills.py` correctly parses and installs list/comma-separated targets.
- [ ] Skills are only deployed for configured/selected agents.
- [ ] Ignored folders added to `.gitignore` are root-anchored with a leading `/`.
- [ ] Integration and unit tests are written, run, and pass successfully.

## Risk Mitigation

### Risk 1: Broken non-interactive execution from missing inputs

If `NON_INTERACTIVE` is enabled but a sub-prompt still blocks waiting for input, the script will hang or fail in automated CI.

#### Mitigation

We will rigorously test both `--yes` and `--no` modes via automated test scripts redirecting standard input to `/dev/null` (`< /dev/null`) to guarantee they never block or hang on interactive prompts.
