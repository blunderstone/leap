# Addressing Issue #36: Setup Script and Migration Gaps Goals

**Author:** [F. Andy Seidl](https://www.linkedin.com/in/faseidl/)<br>
**Date:** 2026-08-28

---

## Quick Summary

Address multiple defects, design gaps, and documentation omissions discovered during workspace bootstrap and migration to LEAP v1.1.0-beta.0.

## Executive Summary

When bootstraping and migrating repositories to LEAP `v1.1.0-beta.0`, several friction points and technical gaps were identified (GitHub Issue #36). These include gaps in project-wide Markdown linting, template bugs in setup scripts, over-installation of custom agent skills, gitignore shadowing risks, automation hurdles for multi-repository scripts, and missing guidance for submodule updates and taxonomy of non-markdown artifacts.

This feature resolves all eight sub-issues across the codebase, ensuring robust automation, clean templates, comprehensive workspace linting, precise skill installation, and complete documentation for submodule migrations and feature artifact organization.

## Risk and Complexity Assessment

**Overall Risk:** LOW

The changes focus on repository configuration, helper scripts (`setup-leap.sh` and `install-skills.py`), and documentation guides. No core product or linter logic is impacted.

**Overall Complexity:** LOW to MEDIUM

Requires careful updates to shell and python scripts to implement non-interactive flag support, list/comma-separated skill installations, and root-anchored ignore patterns, while ensuring that the changes are backed by automated tests.

## Objectives

1. Establish unified project-wide Markdown linting in the LEAP repository using `.check-md.yml`.
2. Fix all template errors and formatting violations in files generated by the setup script.
3. Improve user experience by recommending modern workspace skills in the setup closing message.
4. Restrict skill installation to only those agents selected by the user.
5. Eliminate gitignore shadowing risks by using root-anchored ignore patterns.
6. Provide fully automated, non-interactive CLI flags for `setup-leap.sh`.
7. Document clear migration paths for existing submodules in `guide-installation.md`.
8. Define clear taxonomy rules for non-markdown artifacts in feature folders in `guide-document-taxonomy.md`.

## Requirements

### Functional Requirements

- **REQ-1: Repository-Wide Markdown Linting:**
  - Create a root-level `.check-md.yml` configuration file specifying exclusions (`.venv`, `htmlcov`, agent-specific folders, and `.bak` files).
  - Update `scripts/run-all-checks.sh` to run `check-md` project-wide instead of restricting it to `kb/`.
  - Fix all existing Markdown linting violations in repository files outside `kb/` (such as issue templates, licenses, and developer notes).

- **REQ-2: Lint-Clean Templates:**
  - Correct the heredoc templates inside `scripts/setup-leap.sh` (such as `CLAUDE.md`, `GEMINI.md`, etc.) to guarantee they have correct blank lines and pass `check-md` with no violations immediately upon creation.

- **REQ-3: Modern Skill Promotion:**
  - Update the closing instructions of `scripts/setup-leap.sh` to guide the user to run modern workspace skills like `/leap-start` rather than suggesting manual prompts.

- **REQ-4: Tailored Skill Installation:**
  - Modify `scripts/install-skills.py` to support comma-separated target agents (e.g. `gemini,cursor`).
  - Update `scripts/setup-leap.sh` to track which agents were configured and pass only those configured agents to `install-skills.py` (avoiding installing skills for declined agents).

- **REQ-5: Root-Anchored Gitignore:**
  - Update `configure_gitignore` in `scripts/setup-leap.sh` to use root-anchored ignore patterns (with a leading slash `/` like `/.claude/` or `/.gemini/`) to avoid accidentally shadowing files in nested project subdirectories.

- **REQ-6: Non-Interactive Setup & Flag Support:**
  - Standardize all setup prompt defaults to "no" to prevent accidental modifications.
  - Implement full non-interactive flag support (`--yes`/`-y`, `--no`/`-n`, and individual component flags like `--claude`, `--gemini`, `--cursor`, `--skills`, etc.) in `scripts/setup-leap.sh`.
  - Ensure that when run non-interactively, the script executes without requesting input.

- **REQ-7: Submodule Migration Guide:**
  - Document the step-by-step path for migrating or updating an existing `leap` submodule pointer or repository URL in `kb/guide-installation.md`.

- **REQ-8: Non-Markdown Taxonomy Guidance:**
  - Document the guidelines for placing and separating non-markdown artifacts (scripts, baselines, configs) within `kb/feature/` feature directories in `kb/guide-document-taxonomy.md`.

### Non-Functional Requirements

- **Robustness:** Ensure both interactive and automated/non-interactive setup flows have comprehensive error handling and exit codes.
- **Portability:** Keep setup scripts POSIX-compliant/compatible with macOS and standard Linux distributions.
- **Maintainability:** Align additions in `setup-leap.sh` and `install-skills.py` with established styles (comments, styling, logging).

### Testing Requirements

- **Unit and Integration Tests:**
  - Write or update tests in `scripts/tests/test_install_skills.py` to verify comma-separated agent installations.
  - Write or update tests in `scripts/tests/test_pre_commit_installation.sh` or create a dedicated script test to verify interactive/non-interactive modes of `setup-leap.sh`.
  - Maintain a target of 90%+ code coverage for Python tests, and verify shell scripts pass their assertions cleanly.

### Documentation Requirements

- Complete updates to `kb/guide-installation.md` and `kb/guide-document-taxonomy.md` following LEAP Markdown formatting standards.
- Fully document CLI options in `setup-leap.sh --help`.

## Success Criteria

- [ ] A root-level `.check-md.yml` configuration is added and used.
- [ ] `scripts/run-all-checks.sh` successfully lints the entire repository.
- [ ] All template-generated guides (such as `CLAUDE.md`) are verified to be lint-clean upon creation.
- [ ] Setup script closing instructions promote modern skills.
- [ ] Custom skills are only installed for selected/configured agents.
- [ ] Gitignore patterns added by the setup script are root-anchored with a leading slash.
- [ ] Non-interactive automation is supported via CLI flags and verified via test execution.
- [ ] Submodule migration instructions are documented in `kb/guide-installation.md`.
- [ ] Rules for non-markdown artifacts are documented in `kb/guide-document-taxonomy.md`.
- [ ] All automated check suites and tests pass successfully.

## Constraints

- Changes to Python or shell scripts must support Python 3.10+ and standard bash environments on macOS/Linux.

## Assumptions

- We assume that `check-md` is globally available or locally executable on the test environment as standard.

## Out of Scope

- Upgrades or structural modifications to the linter engine `check-md` itself.
