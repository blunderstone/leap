# Fix pin-leap.sh Heredoc Corruption Goals

**Author:** [faseidl](https://github.com/faseidl)<br>
**Date:** 2026-08-31

---

## Quick Summary

Fix inline code (backtick) corruption in generated markdown templates, dynamically retrieve the host base branch, and check generation command status during LEAP Level 1 document generation in `pin-leap.sh`.

## Executive Summary

The `scripts/pin-leap.sh` script automates pinning the LEAP submodule inside a parent repository and bootstrapping the Level 1 compliance documents (`goals.md` and `completion-summary.md`). However, it currently outputs these files using unquoted heredocs (`cat <<EOF`). Because Markdown inline code utilizes backticks (e.g. `` `some-code` ``), Bash interprets these backticks as command substitutions, running empty commands, discarding the backtick contents, throwing a wall of terminal errors, but then falsely reporting a successful generation.

This task will fix this corruption. We will ensure that markdown backticks are preserved intact while still allowing target version interpolation. We will also dynamically resolve the host repository's base branch instead of hardcoding `main`, and verify the exit code of the document creation process to ensure failures are caught and reported accurately.

## Objectives

1. Prevent Markdown inline code (backtick) command substitution and variable leakage during LEAP Level 1 document generation in `pin-leap.sh`.
2. Dynamically determine the default base branch of the parent repository instead of hard-coding `main`.
3. Check execution status of the document generation block so that any error prevents showing a misleading success message and terminates the script with a non-zero exit code.
4. Enhance the automated tests in `scripts/tests/pin-leap.test.sh` to prevent regressions in backtick retention, base branch detection, and generation status checking.

## Requirements

### Functional Requirements

- **REQ-1:** Level 1 compliance files (`goals.md` and `completion-summary.md`) generated by `scripts/pin-leap.sh` must retain all backticks and inline code blocks verbatim.
- **REQ-2:** The target version string (e.g., `$TARGET_VERSION`) must be successfully interpolated within the generated files.
- **REQ-3:** The host default branch configured in `completion-summary.md` must be dynamically queried from the parent repository (`origin/HEAD`) and default to `main` only if unavailable.
- **REQ-4:** If directory creation or document generation fails, `pin-leap.sh` must exit with a non-zero code and not print the success message.

### Non-Functional Requirements

- **Compatibility:** Must remain compatible with standard Bash shells on macOS and Linux (e.g., standard Git environments).
- **Maintainability:** Refactor the script to use robust/clean generation strategies that are safe from future additions of backticks, dollars, or backslashes.

### Testing Requirements

- **TDD Verification:** Create or update assertions in `scripts/tests/pin-leap.test.sh` to verify:
  1. The generated `goals.md` and `completion-summary.md` do indeed contain the expected backtick blocks.
  2. The generated `completion-summary.md` dynamically shows the default/base branch.
  3. No "command not found" errors are printed during document generation.

### Documentation Requirements

- Update inline comments in `scripts/pin-leap.sh` to explain the safe heredoc generation approach.

## Success Criteria

- [ ] Level 1 compliance documents generated by `pin-leap.sh` retain all backticks intact without execution errors.
- [ ] Target version interpolation in generated files works perfectly.
- [ ] Base branch configuration in generated files is dynamically detected and populated.
- [ ] Generation failures correctly trigger script failure instead of unconditional success messages.
- [ ] All automated tests in `scripts/tests/pin-leap.test.sh` pass.

## Constraints

- Must work in a standard submodule setting where `pin-leap.sh` is invoked from parent repository level.

## Assumptions

- Standard `sed` utility is available on host environment (supporting POSIX syntax).
- `git` is installed and the parent directory is a valid git repository.

## Out of Scope

- Adding more compliance levels beyond Level 1.
- Fully automated git push or remote operations.
