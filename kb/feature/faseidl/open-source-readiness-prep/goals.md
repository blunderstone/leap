## Quick Summary

---

## Executive Summary

As LEAP prepares for its public launch under Blunderstone LLC, several open-source legal and workflow issues must be addressed. We need to ensure all repository documentation consistently markets LEAP as **Open Source** under the **Apache-2.0** license, and purge any legacy or obsolete references to "Source-Available" or "Community Scale License" that were once contemplated but are now defunct.

Furthermore, we must resolve key agent-instruction and setup experience improvements: instructing AI agents that `check-md` is globally runnable, requiring all Markdown references to GitHub issues to be explicitly hyperlinked, and hard-gating agents at phase boundaries so they never proactively jump to subsequent phases without explicit developer approval.

Finally, we must conduct a comprehensive audit of all internal hyperlinks across the repository's Markdown documents (such as the link to the Contributing Guide in `README.md`) to guarantee that all cross-references are 100% valid, accessible, and free of dead ends.

---

## Objectives

1. Audit and adjust READMEs and corporate copy to ensure LEAP is cleanly, consistently, and correctly marketed as **Open Source** (Apache-2.0), purging any defunct "Source-Available" or "Community Scale License" references.
2. Configure global agent instructions in `setup-leap.sh` templates so that all incoming AI agents recognize they can execute `check-md` directly from any directory.
3. Update Markdown documentation guidelines in `kb/best-practices-markdown.md` (and related templates/linters) to explicitly enforce hyperlinked GitHub issue references (e.g., `[#14](https://github.com/blunderstone/leap/issues/14)`).
4. Refine phase gating and skill awareness in all generated agent instruction files (`CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`, `.cursorrules`) and root `GEMINI.md`. They should direct agents to the specialized LEAP skills (like `leap-start`, `leap-dev`) as the preferred path, while providing concise fallback guidance on phase-boundary checkpoints if skills are not used.
5. Audit and sweep all document hyperlinks across the entire repository's knowledge base and roots to resolve any broken cross-document links.

---

## Requirements

### Functional Requirements

- **REQ-1 (Branding Alignment):** Audit the repository and remove/replace any obsolete references to "Source-Available" or "Community Scale License" with clean Open Source (Apache-2.0) messaging.
- **REQ-2 (Global Linter Instructions):** Update all agent instruction templates in `scripts/setup-leap.sh` and workspace guidelines to explicitly state that `check-md` is globally installed and runnable from any subdirectory.
- **REQ-3 (Hyperlinked Issue Enforcement):** Add a guideline to `kb/best-practices-markdown.md` stating that any mention of a GitHub issue must be formatted as an explicit hyperlink to the issue URL on GitHub (e.g., `[#14](https://github.com/blunderstone/leap/issues/14)`).
- **REQ-4 (Skills and Phase Gating Guidance):** Update all agent template files generated by `scripts/setup-leap.sh` (i.e., `CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`, `.cursorrules`) and ensure root `GEMINI.md` direct agents to specialized workspace skills as the preferred path, while keeping fallback phase-boundary gating guidance concise and non-redundant.
- **REQ-5 (Hyperlink Integrity Sweep):** Audit and sweep hyperlinks between all Markdown documents in the repository (e.g., cross-file anchors, relative links, template files) to resolve any broken or fragile links (such as the Contributing Guide link in `README.md`).

### Non-Functional Requirements

- All modified Markdown files must strictly pass `check-md kb/` with zero formatting violations.
- Maintain high-quality, professional English and formatting standards throughout all documentation.

### Testing Requirements

- Verify that `scripts/setup-leap.sh` still loads and runs correctly.
- Run `check-md` over all modified and created Markdown files to verify 100% compliance.
